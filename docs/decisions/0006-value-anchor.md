# ADR-0006: 价值锚点——注意力编译器 + 本地世界中介 + 社区规则资产

- **状态**:已采纳（2026-08-22，经第一性原理讨论后定稿）
- **关联决策**:审计分歧 1（存亡级）
- **相关文档**:`docs/ROADMAP-STRATEGY.md`；`docs/archive/plans/2026-07-29-phase4-execution-layer-pivot.md`（工作区已删，git 可恢复）

## 背景

Phase 4 计划的核心前提是**"LLM 在逃离 bash"**：执行成功导向的 LLM 会自发从复杂 bash 组合转向 Python 脚本与 typed tool，因此价值锚点应从"解析 bash CLI 输出"迁移到"解析 Python 脚本失败"。该前提未经验证，且两种极端选择风险都高：全面转向（A）可能在前提错误时放弃积累，维持现状（B）可能在前提正确时价值蒸发。

## 讨论结论（第一性原理）

### 公理（确认成立）

1. **注意力稀缺**：模型上下文会变大、成本会下降，但注意力是概率性的——输出噪声越大，关键信息被稀释的概率越大。效率提升是历史主线，编译层价值随模型变强**衰减但不归零**；
2. **载体外生**：agent 选择 shell/Python/typed tool 取决于期望成功率，不由 arshy 决定——arshy 只能跟随载体；
3. **本地世界事实无法从输出推出**：git 状态、源码上下文、历史执行记录必须由工具提供，模型能力提升替代不了；
4. **开源项目无护城河，需要楔子与飞轮**：可持续优势是默认选择、社区贡献者、数据飞轮、信任——都靠用户与时间积累，不靠保密。

### 关键观察

- "逃离 bash"是**窄的**：逃的是"bash 作为组合语言"（批量处理文件时组合复杂易错），不是"bash 作为工具接口"（pwd/ls/cd/cat 和 cargo/docker/kubectl 不会逃）；
- parser 是 AI 可批量生成的规则资产：**数量不是壁垒**；壁垒迁移到验证流水线（fixture 门禁）、按需生成（遥测 gate）、集成深度（context/git/生命周期）；
- 对开源项目，低贡献门槛是增长引擎，parser 资产化是**利好**而非威胁。

## 决策

1. **北极星**：arshy 是"注意力编译器 + 本地世界中介 + 社区可贡献的规则资产"——把给人看的输出编译成给 agent 看的事实，把本地事实接上来，让社区低成本贡献规则；
2. **载体三层跟随**：
   - 第 1 类（轻量检查，pwd/ls/cd/cat/git status）：bash 永留，短路径零开销，**零投入**；
   - 第 2 类（重型工具，cargo/docker/kubectl/构建测试）：CLI 永留，**深耕**（按 Phase 4 三层分类执行）；
   - 第 3 类（批量组合，重命名/替换/数据处理）：Python 胜出，**接住**——生命周期 + 关联 + 记忆，解析只做薄的；
3. **parser 按需生成 + 验证流水线**：不做广度竞赛；用使用遥测 gate 生成，fixture/ReDoS/准确率门禁保证质量；候选方向：从"未解析输出"自动建议 parser；
4. **测量驱动分配**：Q1 载体分布、Q2 parser 真实使用、Q3 修闭环、Q4 模型升级影响——数据回来再调资源比例。

## 理由

1. 公理 2 确认：编译层价值衰减但不归零，arshy 的定位是"编译"（无损转译）而非"压缩"（有损）；
2. 用户实测直觉（批量组合才逃 bash）使"分层退化"前提精确化，三层策略与观察吻合；
3. 开源第一个项目的理性选择：资源投给"学习 + 用户反馈 + 贡献面"，不做战略豪赌；
4. 4.2（Python 关联增强）成本极低且复用现有管道，是任何方向下都该做的保险。

## 后果

- **正面**：决策 1 收敛，不再有 A/B 豪赌；资源分配有了明确的三层框架和测量触发；
- **动作**：① 4.2 经代码核查已由 crash 层覆盖（见"后续待办"），不新建 parser；② Q1 载体分布已落地（2026-08-22）；③ 把项目推向第一批真实用户；
- **叙事**：护城河表述从"37 parser"改为"编译层 + 本地世界 + 数据飞轮"；37 不再是软上限争论点，按需生成取代广度目标；
- **风险**：第 3 类占比若快速放大，需按 Q1 数据上调 Python 投入——触发条件已写明。

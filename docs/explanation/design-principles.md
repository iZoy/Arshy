# 设计原则

## 核心约束

Arshy 围绕六个约束设计：

### 1. 零开销短路径

简单命令（`ls`、`echo hello`、`cat file`）必须以原生 shell 的速度执行。

实现：`is_short_command()` 判断命令是否"短"（≤80 字符、≤5 词、无管道/重定向/watch 标志）。短命令跳过数据库写入、parser 会话、事件流，直接返回 stdout。Agent 感知不到延迟差异。

### 2. 结构化事件，非文本流

AI Agent 需要机器可解析的输出，而非人类可读的日志。

设计决策：所有命令输出经过 parser 管道，产生结构化 `TaskEvent`（类型、严重度、错误码、位置）。Agent 查询事件而非解析文本。

### 3. 持久会话，非一次性进程

命令执行的结果必须可查、可追、可统计。

设计决策：所有任务和事件存入 SQLite。Agent 可随时查询历史任务、查看输出、统计失败率。数据库支持自动清理和 WAL 模式。

### 4. 安全边界

Agent 可以执行任意命令，但系统必须有安全兜底。

设计决策：三层安全 — 命令黑名单正则、可选白名单模式、沙箱路径限制。审计日志记录所有执行。默认 `access_level = "full"` 允许全部命令，可收紧为 `read_only`。

### 5. 可扩展解析

新工具的输出格式不断出现，解析能力必须可扩展。

设计决策：三级 parser 架构 — TOML 声明式（80% 覆盖）、Rhai 脚本（15%）、Crash/Raw 兜底（5%）。用户可添加自定义 parser，支持热重载，无需重新编译。

### 6. MCP 原生

Arshy 是为 AI Agent 设计的，不是为人类设计的 CLI 包装器。

设计决策：MCP 协议是主要接口，CLI 是辅助接口。工具定义、资源暴露、通知推送都遵循 MCP 规范。`--from-mcp` 标志切换到 stdio proxy 模式。

## 架构决策

| 决策 | 理由 |
|------|------|
| Unix Domain Socket 而非 TCP | 本地安全性、文件权限控制、无端口冲突 |
| JSON Lines 而非 WebSocket | 简单、无额外依赖、tokio 原生支持 |
| SQLite 而非文件日志 | 查询能力、WAL 并发、自动清理 |
| 后台 daemon 而非 per-command 启动 | 启动延迟 <5ms、状态持久化、多连接复用 |
| Thompson NFA regex | 保证线性时间匹配，不受恶意输入影响 |
| 单 tokio runtime | 简化内存模型、避免多 runtime 竞争 |

## 不做的事

- 不代理网络请求（只管 shell）
- 不管理虚拟环境或容器（预留 sandbox_mode）
- 不提供 UI（纯协议层）
- 不缓存命令输出（只存事件元数据）
- 不替换 shell（使用系统 `sh -c`）
